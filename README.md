# 명단 검수 에이전트

[![test](https://github.com/Shin-923/roster-agent/actions/workflows/test.yml/badge.svg)](https://github.com/Shin-923/roster-agent/actions/workflows/test.yml)

엑셀 · CSV 명단을 올리면 LLM 이 검증 도구를 골라 쓰며 문제를 찾고 수정안을 정리합니다. **DB 에 쓰는 일은 사람이 승인해야만** 실행됩니다.

행사 참가자 명단은 이메일 오타, `+82` 번호, 중복 행이 섞여 들어옵니다. 사람이 하나씩 고치면 느리고, AI 에게 통째로 맡기면 무엇을 바꿨는지 알 수 없습니다. 이 프로젝트는 판단은 모델에게 맡기고, 저장은 사람과 서버가 막는 구조를 실험합니다.

## 동작

```
업로드 → [에이전트] 명단 살펴보기 → 칸 지정 → 형식 검사 → 중복 찾기 → 수정안 · 제외 기록
       → DB 반영 요청 ── 멈춤 ──> 사람: 승인 / 거절
                                   승인 → 서버가 다시 검사(형식 + 중복) → 통과할 때만 저장 + 변경 이력
                                   거절 → 모델에게 「거절됨」 전달, 저장 없음
저장 뒤 → 사람이 배치 단위로 되돌리기 가능
```

진행 상황은 SSE 로 화면에 바로 밀어 줍니다. 도구를 하나 쓸 때마다 목록이 늘어납니다.

| 도구 | 종류 | 하는 일 |
|---|---|---|
| `inspect_sheet` | 읽기 | 칸 이름 · 행 수 · 앞 5행 |
| `set_column_mapping` | 읽기 | 원본 칸 → 이름 · 이메일 · 휴대폰 · 언어 (없는 칸이면 거부) |
| `validate_rows` | 읽기 | 빈 값 · 이메일 형식 · 휴대폰 번호(국내 휴대폰으로 정규화 가능 여부) |
| `find_duplicates` | 읽기 | 이메일 또는 휴대폰이 같은 행 묶음 |
| `propose_fix` / `propose_skip` | 기록 | 수정안 · 제외안 (DB 에 쓰지 않음) |
| `apply_to_db` | **쓰기** | 사람 승인 뒤에만 실행 |

## 설계 결정

- **도구 실행 루프를 직접 작성.** SDK 의 자동 실행기를 쓰지 않았습니다. 쓰기 도구가 나오면 루프를 멈추고 HTTP 요청이 끝난 뒤 승인을 기다려야 하기 때문입니다 (`server/agent.ts`).
- **한 턴의 모든 `tool_use` 에 결과를 한 메시지로 돌려줌.** 읽기 도구는 바로 실행하고, 쓰기 도구는 하나만 대기시킵니다. 같은 턴에 쓰기를 두 번 요청하면 두 번째는 오류 결과로 돌려줍니다.
- **승인해도 서버가 다시 검사.** 모델이 「다 고쳤다」고 말해도 수정안을 적용한 뒤 형식 문제나 중복이 남아 있으면 저장을 거부합니다. 같은 세션의 두 번째 반영도 거부합니다 (`server/tools.ts`).
- **무엇을 바꿨는지 남김.** 저장할 때 `changes` 표에 행 번호 · 원본 값 · 저장 값 · 사유를 같은 트랜잭션으로 넣습니다. 명단만 저장되고 이력이 빠지는 경우는 없습니다 (`server/db.ts`).
- **되돌리기는 사람만.** 배치 단위로 지우는 기능은 HTTP API(`DELETE /api/batches/:id`)에만 있고 모델 도구에는 넣지 않았습니다.
- **실행은 뒤에서, 진행은 SSE 로.** 실행 · 승인 요청은 바로 응답하고 에이전트는 뒤에서 돕니다. 상태가 바뀔 때마다 `GET /api/sessions/:id/events` 로 화면에 보냅니다. 새 라이브러리 없이 Fastify 응답 스트림에 직접 씁니다.
- **모델이 값을 지어내지 못하게.** 시스템 프롬프트에서 원본에 없는 이메일 · 번호를 만들지 말고, 고칠 근거가 없으면 제외로 기록하라고 지시합니다.
- **MCP 서버는 읽기 전용.** 같은 검증 도구를 `npm run mcp` 로 MCP 클라이언트에 공개하지만, 쓰기 도구는 넣지 않았습니다. 쓰기는 승인 화면이 있는 웹에서만 합니다 (`server/mcp.ts`).
- **턴 상한 25.** 모델이 도구를 끝없이 부르면 오류로 멈춥니다.

## 실행

Node 22 이상.

```bash
npm install
cp .env.example .env        # ANTHROPIC_API_KEY 입력
npm run dev:server          # API  http://127.0.0.1:3001
npm run dev:web             # 화면 http://localhost:5173
```

`data/sample.csv` 에 일부러 문제를 넣은 7행이 있습니다(이메일 도메인 누락, `+82` 번호, 중복, 빈 이메일, 유선 번호, 띄어쓴 번호).

**API 키가 없으면 재생 모드로 돕니다.** 실제 모델 대신 정해진 순서로 도구를 부르는 가짜 모델(`server/replay.ts`)이 `sample.csv` 를 처리합니다. 화면에 「재생 모드」가 표시됩니다. 화면 · 승인 · 이력 · 되돌리기 흐름을 키 없이 볼 수 있지만, 판단은 하지 않습니다.

MCP 클라이언트 설정 예:

```json
{ "mcpServers": { "roster-validator": { "command": "npx", "args": ["tsx", "server/mcp.ts"], "cwd": "<이 폴더>" } } }
```

## 테스트

```bash
npm test          # 19개
npm run typecheck
```

푸시할 때마다 GitHub Actions 가 같은 두 명령을 돌립니다(`.github/workflows/test.yml`, Node 22 · Ubuntu).

`tests/agent.test.ts` 는 실제 API 대신 정해진 응답을 돌려주는 가짜 모델을 씁니다. 확인하는 것:

- 모든 `tool_use` 에 결과가 한 메시지로 돌아가는지
- 쓰기 도구에서 멈추고, 승인 전에는 DB 가 비어 있는지
- 승인하면 4건 저장, 거절하면 0건 저장 + 모델에게 거절 전달
- 쓰기 요청 두 번 → 하나만 대기
- 끝없는 도구 호출 → 상한에서 오류
- 형식은 맞는데 중복이 남은 명단 → 저장 거부
- 변경 이력(수정 · 형식 맞춤 · 제외)이 남고, 배치 되돌리기로 명단 · 이력이 함께 지워지는지
- 재생 모드로 승인 화면까지 가고, 도구마다 상태 변경 알림이 나가는지

## 개발하며 고친 것

| 증상 | 원인 | 고친 방법 |
|---|---|---|
| 형식 검사를 통과하면 중복 행도 저장됨 | 승인 후 서버 재검사가 형식만 보고 중복은 안 봄. 모델이 중복을 빼먹으면 그대로 들어감 | 재검사에 중복 검사 추가, 실패 테스트를 먼저 쓰고 고침 |
| 같은 턴에 쓰기 도구가 목록 중간에 오면 API 오류 | 쓰기 도구에서 바로 멈춰 뒤쪽 `tool_use` 에 결과가 없었음 | 읽기 도구를 모두 실행한 뒤 쓰기 하나만 대기, 나머지 쓰기는 오류 결과로 반환 |
| 개발 서버에서 테스트 0개 | Vite 루트가 `web` 이라 Vitest 가 `tests/` 를 못 찾음 | `vitest.config.ts` 분리 |

## 기술

TypeScript · Node.js 22 · Fastify 5 · React 19 · Vite · Anthropic SDK (Tool Calling) · MCP SDK · Drizzle ORM · SQLite(better-sqlite3) · exceljs · zod · Vitest

## 알려진 한계

- 세션을 메모리에 둡니다. 서버를 다시 켜면 진행 중인 검수가 사라지고, 서버를 여러 대로 늘릴 수 없습니다. 늘릴 때는 DB 나 Redis 로 옮깁니다.
- 휴대폰 정규화는 국내 휴대폰(010) 기준입니다. 해외 번호는 문제로 표시만 합니다.
- `exceljs` 의존성에 moderate 등급 취약점 2건이 `npm audit` 에 보고됩니다. 로컬 데모 범위라 그대로 두었습니다.
- 인증이 없습니다. 로컬(127.0.0.1)에서만 열립니다.
- 재생 모드는 `sample.csv` 전용입니다. 다른 파일은 실제 API 키로 실행해야 합니다.
